## 尺度与交付

逻辑格26×26。每块核心32×32格，即832×832；四侧各4格/104px美术余量，归一化源图1040×1040。四块核心拼后64×64格，即1664×1664。原生生图器输出1254方图，保存在raw；1040只是导出规范，并非声称工具原生输出就是1040。

最终可用的四张核心PNG：

- `chunks/01_NW_core.png`，世界左上角(0,0)：西岸来路、追索人院地
- `chunks/02_NE_core.png`，(832,0)：东岸钟架平台、钟房预留地
- `chunks/03_SW_core.png`，(0,832)：西侧南堤、断桥西残端
- `chunks/04_SE_core.png`，(832,832)：东侧南堤、暗渠方向

四张最终PNG全部832×832，完整显示即可，渲染裁切矩形均为(0,0,832,832)。只有normalized/中的1040源图才用(104,104,832,832)取核心。最终核心已经包含接缝补绘，不要再次叠加seam，也不要把1040余量图当核心直接排布。

四张核心不是将一张新生完整全景切成四块：NW/NE/SW/SE各自独立生图，SE独立修订一次；后续局部接缝补绘按覆盖矩形分别合成到每张独立核心。原始核心`*_core_base.png`、实际参考带和补绘图均保留。全景预览只由素材真实组合产生，没有另行生全景。

## 台本空间与可扩展边

保留《旧渡口_场景与通路》与N1台本的相对拓扑：西岸进入与追索人平台→南侧窄堤→东侧室外钟架→独立钟房→暗渠。断桥的两侧残端仍隔着水，不能误当第二条通路。钟仍应悬挂、绳被割断的剧情由后续独立钟架表达，本地面不烘焙钟或绳。

地块外缘继续为土地、道路或河道，不围成一座小岛。北、南水道和东西道路都可接下一批。钟房、钟架、NPC、前景物件继续独立；本轮没有更改旧三房间拓扑或把这张美术图当成已实现大世界。

实绘道路约104–130px（4–5格）、南堤约96–104px（约4格）、河宽约234–286px（9–11格）。建筑预留地显著小于一块地，人物35×44尺寸框可见比例。画稿未完全服从最初水岸数值：横缝y832附近西岸约x750、东岸约x1000，路中心约x365和x1305，南堤约y1316..1416。`chunk_layout.json`同时保留初始目标与实绘近似值；锚点仅为美术建议，不能直接推导碰撞、导航或旧房间落点。

## 共用边带与补绘

后块不是凭记忆画边界：NE引用NW实际右侧208px带，SW引用NW实际底部208px带，SE同时引用NE底部与SW右侧208px带。文件在sources/，完整输入链在generation_manifest.json。

独立生图仍产生偏差，因此增加5张image_gen专用接缝绘画：

1. 南堤水平连续带，世界矩形(416,1170,832,416)
2. 东西横向接缝带，(0,624,1664,416)
3. 中央纵向河道带，(624,0,416,1664)
4. 断桥残端附近水纹修补，(624,936,416,416)
5. 南堤下游水色连续带，(416,1144,832,520)

最终核心包含这些补绘；完整顺序含一次桥面回叠，见JSON中的production_only_seam_operations_in_order。边缘只有8px透明衔接整理，没有大范围模糊盖住道路断线。接缝内容本身由image_gen绘制；ImageMagick只做选区裁切、尺寸归一化、alpha边缘、真实合成和说明线框。未用Python或程序绘制景色。

## 局部视觉检查

实际查看了全部输出、整体拼图、中央四块交点、东西横缝、上下纵缝、断桥与南堤局部：

- 河水：相邻块沿同一南北水道延续，小斜纹方向一致。最初水色的矩形断口和桥下横切经过局部补绘消除；静态纹理只表达流向建议，不是水流动画。
- 岸线：两岸连续，交点没有重复岸墙或白缝；低石岸的宽度和视角总体一致。外缘依旧开放。
- 道路：两条南北路通过横向分界，宽度近似稳定；南堤在中央块界没有高度台阶，两侧岸接道路仍连通。断桥残端互不接触。
- 光线与尺度：全图为左上方柔光、正交俯视的小体量石块；没有在某个块中突然出现近景建筑或大人物。

仍有限制：水纹高光偏强，桥下两条白色波纹有人工感；接缝带与原稿的细颗粒密度仍有局部差异。当前是可展示的接缝试制候选，不宣称像素级美术风格已统一、动画无缝、原生调色板通过或生产验收。没有继续为这些问题无限生图。

AE=0只证明交付核心重新拼图与预览一致，不能替代上述自然度观察，更不能证明导航、碰撞或游戏运行。

## 数据与来源

- `chunk_layout.json`：世界坐标、源核心裁切、最终渲染裁切、halo、相邻块、实际连接点、候选锚点和接缝覆盖矩形
- `generation_manifest.json`：10次内置image_gen调用，4块初稿＋SE一次修订＋5张局部补绘，提示词与实际引用输入
- `TRANSFORMS.txt`：裁切、归一化、alpha与合成操作
- `sources/`：台本、旧拓扑、旧26px规格与共享边带
- `prompts/`：完整提示词
- `SHA256SUMS.txt`：冻结文件指纹

本目录不提供Godot脚本；工程接入由对应任务处理。推荐只加载四张最终core，位置见JSON；建筑/人物层和逻辑碰撞另行实现与验收。
