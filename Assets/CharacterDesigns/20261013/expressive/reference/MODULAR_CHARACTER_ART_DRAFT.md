# 模块化人物素材制作建议草案

日期：2026-10-13。状态：美术生产方案，尚未制作、接入或验证换装功能。

## 结论与适用范围

需要提前兼容，先统一底模、图层接口和动画帧约定，再扩充装备。已认可的近 1:1 大头紧凑身体、成年面容和清晰表情继续作为视觉方向；现有整身概念图保留，用于确定人物特征。概念图本身不是可换装的原生精灵，正式素材还需重绘被衣物遮住的身体和独立装备层。

本稿不规定正式画布像素数、方向数、动作帧数、帧率或 GameMaker 原点，不把 4 向或 8 向当作原版事实。先核对目标版本及沿用的对象，再锁定这些值。近 1:1 指头部与身体的视觉比例方向，不是画布纵横比或引擎尺寸。

认可 G 风格不代表它已经匹配原版装备尺寸或持握姿势。若复用原版装备图，需逐项对齐头部/身体轮廓、锚点及动作；大头比例若无法自然容纳原版头盔，应保留 G 作为概念方向，另做运行尺寸适配，或为该体型重绘装备，不能直接套图后声称兼容。

## 按需求分三档

- **固定外观 NPC**：没有换装需求，只交付必要动作的整身帧；可从分层母版合成，也允许专门手绘。无需为每名路人制作完整装备库。
- **少量预设 NPC**：如工作服、出行服、受伤状态。复用底模和身份层，按已定义的几套外观导出整身序列；预设以外的组合不承诺支持。
- **完全换装角色**：按装备槽和兼容体型生产部件，所有声明支持的动作、方向必须覆盖；运行时组合或预先烘焙由引擎适配核验决定。

同一体型的一套衣甲应服务多个人物，不为每个 NPC × 每件装备重新画一遍。首期只建一个成人体型；脸、肤色、发型、表情和配色形成身份差异。明显不同的身高、肩宽、体态以后建立独立体型族，并明确哪些装备需适配，不能把任意体型都强行套进一个底模。

人类、精灵或不同性别并不自动各需一整套底模；按实际身形、身高及头耳轮廓决定是否共享体型族。精灵耳等特征可做身份部件，但要进入头盔覆盖规则。装备须声明适用的体型族，不以人物种族或性别标签代替贴合检验。

## 分层母版与遮挡

建议母版至少保留以下独立内容；这是逻辑分类，不是任何方向都不变的绘制顺序。

1. 后发：发髻、辫子、后侧长发，可按需要拆远近片。
2. 身体：躯干、左右臂与手、左右腿与脚；保留被服装遮住的必要底形。
3. 头脸与表情：稳定头形和五官定位，表情用替换帧保留清晰眉眼嘴部，不随换甲改变脸型。
4. 衣甲：内衣、上身衣甲、袖、下装、鞋、手套；跨前后侧的部件按遮挡拆片。
5. 前发与头盔：额发、鬓发、帽盔和面罩；开面盔保留可见表情，全覆面盔按真实遮挡隐藏脸部。
6. 手持物：主手武器、副手盾牌或物品，必要时分成手后、手前片，使手掌能正确包住握柄。
7. 背部物：披风、背包、背负武器或工具，按姿势区分背后及绕到前侧的部分。

每个“动作 × 朝向 × 逻辑帧”可覆盖绘制顺序、可见部件和握点。转身时前后臂、盾牌、武器、披风的遮挡会改变，不能使用一张永久固定的层序表。左右手按角色解剖侧命名，另记录该帧的近侧/远侧；不可仅凭屏幕左右推断惯用手。镜像必须核对非对称装备和人物特征。

## 统一帧接口

- 同一体型的部件共享逻辑画布、像素网格、脚底锚点 `foot_anchor`、动作 ID、视角 ID 和逻辑帧 ID；各层读取同一动画时间轴，不能各自播放导致错帧。
- 逐帧记录头部附着点、左右手握点、背部附着点。装备在对应帧画好透视和轮廓，再对齐附着点；仅移动一个静态武器图不能覆盖所有挥击姿态。
- 美术脚底锚点与引擎精灵原点 `engine_origin` 分开记录。引擎原点、碰撞和点击边界未核实前为待定，不按图片 alpha 外缘推导世界碰撞。
- 母版使用相同画布。打包允许裁透明边，但 JSON 必须保存逻辑画布、裁切偏移及图集矩形，以便还原到同一坐标系；不能让每个部件裁切后各自居中。
- 复用同一图像跨多个逻辑帧须显式映射。缺帧、缺方向或不支持的组合应报错或转到已批准预设，不能默默拉伸、乱镜像或显示错位部件。

低分辨率表达不等于对每帧做骨骼拉伸。优先手绘关键帧、轮廓修正和部件替换；骨骼/附着点可用于对齐与制作辅助，不能代替像素边缘、脸部和手部的逐帧检查。旋转、缩放后的像素若破坏轮廓，需要重绘，不把机械变形直接当成最终帧。

## 头盔与特殊姿态

- **发型和头盔**：为发型划分额发、鬓发、后发、发髻等隐藏区域；头盔声明 `hide_regions` 或逐帧 `hide_mask`。贴头盔可隐藏发髻，开面盔可留下鬓发；无法自然裁掉时提供“戴盔版发型”。隐藏蒙版只用于外观，不混同碰撞掩码。
- **衣甲覆盖**：为躯干、臂腿、内衣及耳部等定义可隐藏区域，避免底层皮肤或内衣从盔甲缝隙错误露出。蒙版随具体装备、姿态和方向变化，不删除母版像素；脱装后恢复正确底层。
- **双手武器**：单独指定双手姿态族、两手握点和前后遮挡，包含持握、蓄力及挥击所需替换帧。副手盾牌必须按装备规则互斥或转为已定义的收纳外观，不沿用单手姿态硬叠。
- **坐姿及其他特殊姿态**：单独检查弯曲腿部、衣摆、长甲、披风、背包与座面的关系。可限制组合、提供专用帧或使用明确预设；不能用站姿下半身压缩得到坐姿，也不能无说明隐藏不兼容装备。

## 导出与引擎适配

保留可编辑的真实分层母版，导出透明 PNG 单帧或 spritesheet，并配 JSON 元数据。把已有整身 PNG 裁成头、身、腿三块不会补全被遮住的结构，也不构成完整换装素材。

建议 JSON 至少记录：

- `schema_version`、资产 ID、体型 ID、装备槽、外观/表情 ID、来源候选与版本/哈希。
- `logical_canvas`、`foot_anchor`、帧图路径或图集矩形、`trim_offset`。
- 动作 ID、视角 ID及其文字说明、逻辑帧 ID、持续时间或待定标记。
- 逐帧附着点、绘制顺序、隐藏区域/蒙版及姿态替换。
- 支持的体型/动作/方向、装备互斥项、缺项状态与明确的回退预设。
- 引擎映射独立区：资源名称、`engine_origin`、碰撞/点击配置、原生状态映射和 `runtime_verified: false`；未核实值写 `null` 并附原因。

两条可选适配路径：

- **运行时组合**：分别导入部件，按装备状态同步帧、遮挡与隐藏规则。需要核实原生绘制流程和装备变更接口，并验证性能与交互。
- **预先烘焙**：用同一套部件离线合成受支持的整身外观及动作序列，再按状态选择精灵。较适合固定/少量预设 NPC；完全换装时组合量会增长，必须先限定支持范围。

PNG/spritesheet + JSON 是拟定的中间交付格式，不代表 Stoneshard 会直接读取这套 JSON，也不代表当前 Mod 已具备任一适配器。两条路径可以共用美术母版，避免提前绑定未核实的运行实现。

装备数值槽与绘制层不必一一对应，一件衣甲可能跨多个绘制层。世界角色外观、背包图标、地面掉落图及肖像也是不同交付项，不能用同一份图自动视作全部完成。原版 NPC 的整身外观接口是否能接玩家装备通道，须单独核验。

## 最小试点与验收

待原版元数据和视觉尺寸核实后，先制作：**1 个成人体型 + 2 套身份外观 + 2 顶头盔 + 1 把单手武器与 1 面盾牌 + 1 把双手武器**。两套外观复用同一身体接口，可用脸、发型、基础服装区分；无需增加第二体型。

先用已确认的一个视角检查站立及握持，再补能暴露前后遮挡的已确认视角。动作试点只选站立、少量移动/攻击关键帧与一帧坐姿检查；完整方向列表、动作清单和帧数依实际游戏核验结果，不在此先写死。试点关键帧通过不等于整套动画完成。

验收要点：

- 两套外观分别测试无盔、盔 A、盔 B；检查发型穿盔、面罩遮挡及露出的脸部表情。
- 分别测试空手、单手加盾、双手武器；检查双手/副手互斥、握柄脱手和近远侧遮挡。
- 在支持的视角和试点动作上检查脚点稳定、衣甲贴合、肢体穿插、帧同步及坐姿裁切。
- 用原尺寸和整数倍预览检查轮廓与表情；正式游戏同地面并排截图再核验相对尺度、站位、深度、点击和通行。
- 明确记录通过的组合及未覆盖项，再决定扩充装备、动作或体型。未运行的组合不能写成已兼容。

- 项目规则：`AGENTS.md`，2026-10-13 读取；事实、推断与原创方案分开，运行验证不由文档或编译通过替代。
- 已认可方向定位：`Assets/CharacterDesigns/20261013/expressive/hers/spec_lock.md`，记载 Sela G 方向、近 1:1 比例、清晰成年面容；该文件同时明确当前是概念，不是原生精灵转换。
- 技术边界：`src/EmbersAndOaths/Assets/ConceptDrafts/20261012/ART_NATIVE_REQUIREMENTS.md`，2026-10-12 调查。其记录的现有 NPC 复用 `s_peasantfemale_06` 等原生精灵；钟的导入代码、37×50 对话图标、26 像素布置格距均不能作为人物制作规范。
- 上述调查尚未确认目标 NPC 的实际朝向/动作、精灵原点、碰撞和原生装备绘制接口。本稿没有新增原版核验结论；具体原版发现应另附版本、来源定位和实测结果，再修订本稿对应字段。
