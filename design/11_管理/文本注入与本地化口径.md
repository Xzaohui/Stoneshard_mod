# 文本注入与本地化口径

从已实现小样中提取**文本如何进游戏**的口径（只读），供实现轮沿用同一机制。数据 `research/text-injection.json`。

## 机制（含证据行）

| 环节 | 做法 | 证据 |
| --- | --- | --- |
| 对话流注册 | `variable_struct_set(global.__dialogue_flow_data, …)` | `NativeDialogue.cs:114` |
| 逐行文本注册 | `ds_map_set(global.npc_lines_map, _key, _row)` | `NativeDialogue.cs:130` |
| 语言槽选择 | `line_text = array_get(_texts, global.language == 3 ? 1 : 0)` | `NativeDialogue.cs:129` |
| 运行前置 | 控制器在 `__dialogue_flow_data` 为结构体时才接管 | `controller_step.gml:3` |
| 文书原语 | `ReadCheck`／`CarryCheck`／`GiveCode`／`Quote` | `NativeDocuments.cs:39` |

## 口径

- **双语槽序**：数组索引 0＝EN、1＝CN（小样示例：`Toman told me to find Verren's caravan. …` / `托曼叫我来找维伦的商队。这里有一封迟送的信、一张…`）；`global.language == 3` 时取 CN。
- **流结构**：`RootFragment` → `Fragments`（节点指向下一节点、行键或 `@dialogue_end`）；`Speakers` 声明发言人；`Specs` 标 hub／technical／action；`Scripts` 绑定 GML 回调名。
- **注入方式**：文本以 `json_parse` 内嵌进生成代码——**不改 STRG、不依赖外部文件路径**；与"不复制商业资源"的口径一致。
- **文书**：阅读与携带走原生物品机制（ReadCheck／CarryCheck／GiveCode），不另造一套阅读状态。

## 边界

- 只读提取：**未接线、未构建、未部署**；小样行数与结构只作口径参考。
- 语言槽序按小样实测代码判定；若引擎 `global.language` 取值有变，须先核对再批量注入。
- 文本字数、界面排版与字体渲染仍待实机（见 [[待办与已知缺口登记]]）。
