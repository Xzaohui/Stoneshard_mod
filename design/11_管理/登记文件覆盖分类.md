# 登记文件覆盖分类

把 `research/` 下的登记 JSON（127 份，不含 `*-validation.json` 与清单）按**被谁覆盖**分类，回答“哪些数据有人验、哪些只是记录”。登记 `research/registry-coverage.json`，工具 `research/tools/Write-RegistryCoverage.py`。

| 类别 | 份数 | 含义 |
| --- | ---: | --- |
| `validator-direct` | 92 | 校验器直接读（源码出现文件名） |
| `validator-indirect` | 24 | 校验器间接读（参数化 slug／`feedback_source` 等） |
| `tool-output` | 5 | 工具产物（写手/记录器生成，暂无校验器读） |
| `cited-log` | 4 | 调查记录（被设计页引用为证据） |
| `baseline` | 2 | 共享输入（基线／设计模型） |
| `unclassified` | 0 | 未归类（守卫要求为 0） |

## 规则

- **新增“活输入”**（写手或校验器会读的登记）必须落进 `validator-direct` 或 `validator-indirect`：先在工具里写具体路径或可解析 slug，再重跑本页工具登记。
- **工具产物**可以暂无校验器，但必须由已登记的工具生成；若它开始被别的工具读取，就会自动升级为前两类。
- **调查记录**必须被至少一个设计页引用（否则读者无从发现），本页分类即为该引用的现场核对。
- 出现 `unclassified` 即报错：先补引用、补工具或补校验器，再重跑。

## 未归类清单

无。

## 边界

- 分类只看“有没有人读/被引用”，不判断数据本身是否正确；数据正确性由各自校验器负责。
- 间接读的判定基于 slug 词干匹配，可能与实际参数不同；登记里给出命中的校验器名以便复核。
