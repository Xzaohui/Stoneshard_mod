## 一、通用执行方式（所有阶段）

- **分支**：每个阶段在 `story-s200-s202` 之上用 `git worktree add ../wt-<阶段> -b story-<阶段>` 新开工作树。主工作树（小辉负责）不切分支、不 stash、不 reset。提交一律用 `git commit -- <路径>`，按路径限定；push 不用 force。
- **分工**：
  - 大规模批量改写和批量校验交给 Codex（`codex exec --skip-git-repo-check`）或 opencode 的 glm-5.3（`zhipuai-coding-plan/glm-5.3`）。GLM 有速率限制，所以每批不超过约 20 篇，限流时由 Codex 接手。
  - 我负责定规则、抽查、修逻辑问题、同步登记。
- **每轮收尾固定流程**：
  1. 运行 `Record-StructureOptimization.py` 回写哈希；
  2. 全量运行 91 个校验器和 Test-DesignVault，与基线失败清单（24 个）比对，确认没有回归；
  3. 换行恢复为 HEAD 时的格式（CRLF 保持 CRLF，LF 保持 LF）；
  4. 在变更日志里追加一节。
- **不碰**：README.md、根目录 AGENTS.md、CHANGELOG.md、design/AGENTS.md（写手自动刷新的除外）、src/、output/。
- **块约定**：新内容写在 `<!-- OPT-S2xx:BEGIN/END -->` 块里。如果要改块外的原有正文，先确认 NotePreserve 和写手重新渲染时不会覆盖；必要时先改 research/*.json，再用写手重新渲染。
