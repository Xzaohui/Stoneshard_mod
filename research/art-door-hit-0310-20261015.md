## 本地接口证据与判断

只读核对当前安装 0.9.4.25 modbranch 的局部门接口，没有保存原作源码全集。输入 data.win SHA-256 为 `B772EA0883288A60680FF28C39D0579EC5519ED84D833EA1E3C62C7EE6179EC0`。

- 原生 `o_transitions_door` Create 由精灵尺寸和原点计算 grid，并设置原生 cursor；左键实际经 `o_floor_target` 的全局鼠标事件、目标选择和 User 1 触发门的 User 0；原生门 Mouse 4 本身为空。
- `o_floor_target` Mouse 53 在鼠标碰到 `o_unit` 时直接返回。`scr_cursorInteractionSpriteUpdate` 对位于人物后方的交互物也会避让。站在门中央后再点击人物身体不能作为有效门点击；不能清锁或直调转场绕过这些条件。
- `s_doors_all_small`：64×90，原点 (32,32)，bbox=(17,6)..(44,49)。0.3.7 的独立锚点只把原点改到 (32,45)，故实际鼠标矩形相对门坐标为 x=-15..12、y=-39..4。
- 新阶口成品 `s_eao_hd2d_r01_doorway_open`：52×65，原点 (26,52)，alpha 非空范围为 (0,38)..(51,64)，相对门坐标为 x=-26..25、y=-14..12。右侧翻板和下沿有可见像素落在旧门命中范围外。0.3.9 曾点击右侧后变成地面移动，与此不一致相符；它不能单独证明所有点击失败的原因。
- 原生 `scr_barrier_fill_cells_simple(0,0)` 按位置、placelist 和偏移登记逻辑格，不按鼠标 mask 扩张格数。

## 修复范围

七处 N2 门的 `Sprite` 继续使用居中原生锚点，保留原有 grid、目标、到达标签、父对象、原生鼠标/寻路/报警器/保存与转场链。只给这七处 EAO 对象指定独立 `TextureMaskId`，其矩形对齐阶口 alpha 包围范围，复用现有自产图纹理，不增加图像资产或改变可走区。原作对象与 CODE 不修改。

新增只读面板行显示实际 bbox 相对门坐标和原生 pointed 对象，便于区分点中了人物、阶口还是地面。面板不写 cursor/输入/锁状态。开发图形回退模式仍使用同一鼠标 mask，保证交互格不随显示开关改变；回退外观与 mask 差异单独待测。

原生 `scr_draw_highlight` 的 shader 分支读取 `sprite_index`，但门 Create 的 `scr_set_hl(sprite_index)` 传入正资源号，实际令 `shaderHighlight=false` 并令 `sprlight` 指向旧锚点。因此第一轮仅在 Draw 切换 sprite_index 的方案实机仍有竖门高亮，已保留失败截图。修正版只在这一次继承 Draw 中临时切换阶口图和 `shaderHighlight=true`，绘制后恢复两者；`sprlight` 保持原值，原生悬停/高亮条件保留。不把临时显示带进 Create 或其他模拟事件。关闭新素材时仍使用原生显示分支。编译检查核验七门都保留继承调用、临时图案、shader 状态及锚点恢复；视觉仍以修正版实机为准。

`EaoDoorwayHitChecks` 从候选内嵌 PNG 解码 alpha 后独立求包围框，核验序列化 mask、纹理复用、右侧翻板范围，以及七门的居中 Sprite/原生父对象/无自制鼠标事件。候选检查不替代实机点击。
