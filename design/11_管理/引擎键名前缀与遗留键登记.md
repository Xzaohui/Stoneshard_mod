# 引擎键名前缀与遗留键登记

实现侧的存档键与设计登记键**命名口径不同**：已实现的 GML 全部使用 `EAO_` 前缀，而 `research/state-keys.json` 的登记键不带前缀。本页定口径并清点现状（只读扫描，不改源码、不改存档）。

## 口径

- **引擎键名 ＝ `EAO_` ＋ 登记键名**：登记名（如 `resolve_N2`）是设计标识；落库时加 `EAO_` 前缀，避免与原版键冲突（原版键示例：`Reputation1_Steppe`、`follower_loyalty`）。
- 例：`resolve_N2` → `EAO_resolve_N2`；`encountered_N2` → `EAO_encountered_N2`；`presence_N2` → `EAO_presence_N2`。
- 反向不成立：`EAO_` 键不一定来自登记（见下表遗留键）。

## 与 N1 小样的冲突（须在实现时决定）

- 小样用 **`EAO_N1_stage`**（整数阶段）与 `EAO_N1_origin_*`（出发房间/坐标）；登记侧 `N1` 用 **`resolve_N1`**（none/shelter/audit）＋`encountered_N1`＋`presence_N1`＋两个 `callback_*`。
- 实现新批次时只能**二选一**：把小样阶段迁移为登记键（写迁移口径），或保留 `EAO_N1_stage` 作兼容垫片。**OI-03 已定稿（2026-10-14）**：按脚本二选一——N1 小样完整保留样例键至重制；N2 起一律登记键（P1 五键已落地）；同一脚本内不得同时写两套键，不同脚本族并存于同一存档允许。
- 口径全文见 [[状态键映射总表]]「旧档迁移与缺键口径」；证据与迁移建议见 [[N1小样键语义与迁移建议]]。

## 边界

- 本页只读扫描 GML 字面量，不检查运行时读写路径；键的实际生效仍须游戏内验证。
- 不改源码、不改存档、不部署；新增键在实现时先登记 [[状态键映射总表]] 再落库。
