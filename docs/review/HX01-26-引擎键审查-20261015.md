### M2 布尔键用 JSON bool，和既有字符串约定不一致
28 个 heavy_edge 键的 `values` 是 `[false, true]`、`default` 是 `false`（JSON bool），例如 research/state-keys.json:15917 `n4_shift_remedied`；既有 1393 键（receipt、callback 等）一律是字符串 `"false"/"true"`，src 里也按字符串比较。落到 `ds_map` 后，bool 会变成实数 0/1，`== "false"` 永远不成立。建议统一为字符串 `"false"/"true"`。

### M3 键缺失时 src 判定两头落空（默认值未落地）
登记写 `resolve_N7` 默认 `none`，但 src/EmbersAndOaths/Codes/fx_qry_before.gml:6 与 fx_qry_after.gml:6 都先要求 `ds_map_exists`，旧存档缺键时"之前"和"之后"都返回假（FieldQuest.cs:150-158、fx_qry_early.gml:6 同理）。这属于代码侧，由代码负责修：缺键按默认值 `none` 处理（`!ds_map_exists(...) || value == "none"`）。HX 新键将来实现时应统一走一个"读键带默认值"的辅助函数。

### M4 生成器会写 README 并链式重跑
`Write-StateKeys.py`、`Write-EventStubs.py`、`Write-HookMapping.py` 末尾都改写 README.md，新提交又在末尾 `runpy` 调用 `Write-HeavyEdges.py`（如 research/tools/Write-StateKeys.py:167-170）。README 有专人负责，执行任一生成器都会改到它。按约定我没有运行 `Write-StateKeys.py`。建议把 README 写入改成显式开关（如 `--update-readme`），把 HX 重建移到单独的入口。
